# Migration guide

## Upgrading to 1.0.0 (initial release)

This is the first public release — there are no prior versions to migrate from. This document will grow with each breaking change and always state: what changed, why, and the exact steps.

### Conventions from here on

- **Semver.** Breaking changes bump the major version and are documented here.
- **Generated code is version-stamped**: every module header carries the generator version (`Generated by GEORGE GUI @Search v1.0.0`), so you can always tell which release produced a given module.
- **Regeneration is the upgrade path.** Generated modules are self-contained; newer generator versions may emit improved code, but existing modules keep working unchanged.
- **Tools are additive within a major version.** New tools and optional input fields arrive in minor versions; removed or re-typed fields only in majors.

### Renaming an interface kind

If a future release renames a `kind`, the old id will keep working (with a deprecation note in the result) for one major version.

### Palette evolution

Palette hexes are part of the visual contract; adjustments that change contrast characteristics only happen in major versions. Token *additions* (new colors) are non-breaking — the emitted `Theme` table simply gains a field.

## Checking your version

```bash
npx george-gui-search --version   # tool result via any MCP client: george_version
```

Or call the `george_version` tool — the structured response includes the version, interface kinds, palettes and template list.
